## Reader Chatbot Assistant 


### Project overview

This project allows interaction with a locally hosted LLM model by uploading .pdf or image type files to a locally hosted streamlit server in order to have questions answered based on the text within those files. 

The project can be split into three sections: the data pipeline (data.py), the chatbot (chat.py) and the app (app.py).

I initially created a locally-running lightweight chatbot that works via the CLI before working on a dedicated user interface. I decided to make it locally running as didn't want to depend on the availability or compatibility with any external servers as well as the fact that the inputted data is secure. I chose streamlit for the UI due to it's compatibility with machine learning projects and ease of use such as auto formatting chatboxes. 

There are several developmental areas for the project described below.

### Data pipeline

First text is extracted from files using Google's Tesseract optical character recognition OCR engine. The processed files's text content is turned into a list of Langchain documents which are then split into chunks. The chunks are embedded and stored in the vectorstore which is created using FAISS - Facebook AI Similarity Search. 

To process the files, I utilised Google's Tesseract OCR engine for reading PDFS and image files, which can handle lower quality documents but is slow.

I chose FAISS as it extremely quick at similarity searches - this corresponds with searching the vector database for data close to a user inputted 'question vector'. It works locally yet is highly scalable and FAISS integrates well into larger ML workflows with embeddings generated by models. 

To generate the embedding I have used HuggingFace's sentence-transformers/all-MiniLM-L6-v2. This lightweight model was designed to be a paragraph encoder and captures the semantic information, good for information retrieval. 


### Chatbot

The chatbot is designed to extract text from uploaded files and then answer questions about that text via a vectorstore similarity search which returns the chunks most similar to the query, with metadata. It was important to include memory functionality in order to have a meaningful conversation with the chatbot.

I have used a local Ollama llama3.2:3b, small 3 billion parameter model of Meta's llama3.2 which is strong at summarization tasks. Running locally has the advantages of strong privacy and no per-token API cost, however this comes with a lower model capacity.


### App

I have use streamlit in order to create a user interface for the chatbot and the integration was smooth, though temporary files were introduced to recycle the data pipeline.

I leveraged streamlit's session state to hold the llm, vectorstore and the chat history. It made sense to use session state for the chat history as messages go via a chat_message message box. However this change has caused me to loose information the chunk's metadata and needs to be rectified. 


### Future work

#### Upgrading the data injestion pipeline

I would like to implement computer vision to be able to better understand inputted documents, though this may be computationally expensive.

The current OCR process is slow and needs either optimising or a different engine. The current Tesseract + Poppler dependencies requiring the Poppler binaries and I have been having some configuration issues, I suspect that it will not be easy to migrate this to the cloud though this needs investigating.

#### Deploying to the cloud
It would be great to deploy the app to Streamlit Community Cloud where it would be publicly accessible. However this will require an overhaul of the current architecture as the llm will need to be hosted elsewhere to remove local dependencies. 

I explored server hosted llm's though the HuggingFaceEmbeddings endpoint and tried a variety of models but had issues with task and inference provider compatibility. I also tried OPENAI's api but this requires a fee and so is not ideal for initial exploration but certainly and option.

Using cloud based infrastructure for both models and data pipelines would allow access to more compute which would be useful for large datasets or if fine tuning in implemented, though size restrictions from Community Cloud limits would need to be considered.

#### Optimisation

I would like to optimise chunk size and OCR parameters such as dpi - page resolution and psm - Tesseract's page segmentation mode. It would be interesting to se how these would vary across different models.

Implement fine-tuning of the model based on uploaded documents.
